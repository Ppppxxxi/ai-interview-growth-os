# AI 面试成长 OS UI 风格原型设计

## 目标

为桌面端完整产品制作三套可对比的 HTML 视觉原型，帮助确定后续 React UI 重构方向。原型覆盖工作台、开始新面试、我的回答库，使用同一份脱敏示例数据和一致的信息架构。

本轮只验证视觉层级、页面结构、信息密度和主要交互，不修改现有 React 产品代码与数据逻辑。

## 核心约束

- 所有方案避免首屏展示大量信息。
- 页面不罗列功能说明、设计备注、技术边界或教学性文字。
- 每个区域只保留一个主要动作。
- 默认展示摘要，详情由用户选择后展开。
- 使用“开始新面试”“下次可用回答”“我的回答库”等用户语言。
- 示例公司、岗位和面试内容必须虚构且不可识别。
- 以 1440px 桌面端工作流为主要画布。

## 统一产品结构

### 全局导航

左侧固定导航只保留：工作台、开始新面试、我的回答库。数据管理放入低权重菜单，不占用主要导航位置。

### 工作台

首屏只展示：

- 当前岗位。
- 下一步最该准备的一件事。
- 最近一次面试记录摘要。
- 进入回答库或继续准备的入口。

历史岗位、统计和详细复盘不在首屏平铺，通过局部切换或详情面板查看。

### 开始新面试

采用渐进式流程。默认只展示材料输入和轻量岗位归属，不同时展开识别结果、回答生成与保存区域。

流程状态为：导入材料、确认识别、整理回答、完成。顶部仅显示紧凑进度，不为每一步附加解释。

解析后使用主从结构：左侧问题列表，右侧当前问题详情。一次只处理一条问题，避免连续堆叠多张大卡片。

### 我的回答库

默认使用搜索驱动的列表布局。每条结果只展示问题类型、原问题、回答摘要、适用方向和使用状态。选中后在侧边详情面板查看完整回答、来源和反馈。

快捷筛选保持一行，空结果只给一个明确下一步建议。

## 三种视觉方向

### A. 冷静专业型

参考现代项目管理和开发工具的克制界面。使用中性色、细边框、紧凑间距和清晰状态色。强调扫描效率和长期使用稳定感。

风险：控制不好会显得偏后台系统。通过减少表格、弱化边框和突出内容标题缓解。

### B. 内容编辑型

以材料、问题和回答为视觉中心，使用更充分的留白、编辑器式正文和轻量侧栏。强调阅读、修改与沉淀体验。

风险：信息定位速度可能低于专业工具型。通过固定导航、紧凑搜索和清晰选中态缓解。

### C. AI 工作流型

使用双栏任务工作区、紧凑状态轨道和结构化结果区域，强调材料转化为可复用回答的过程。视觉辨识度最高，但不使用大面积渐变、发光装饰或聊天机器人式布局。

风险：容易增加无效视觉元素。所有状态和装饰必须对应真实流程或反馈。

## 对比方式

第一阶段制作三套风格总览，每套展示相同的工作台、开始新面试和回答库缩略界面。用户可直接选择偏好的方向，也可以指定组合，例如采用 A 的导航与 B 的内容区。

第二阶段只展开用户选中的一至两套，制作可交互 HTML 原型，包括页面切换、流程步骤切换、回答列表选择和详情展开。

## 交互与状态

- 所有按钮只执行原型内的可逆状态切换，不写入真实数据。
- 空状态、加载状态和完成状态保持简短，不出现实现说明。
- 当前任务始终有明确主按钮，次要操作降低视觉权重。
- 原型不模拟真实 AI 请求，只展示稳定的脱敏结果。

## 验收标准

- 1440px 桌面视口内，无需滚动即可识别当前页面、当前任务和主要动作。
- 任一页面首屏不存在连续的大段说明文字或多个并列信息模块。
- 三套方案在布局、字体气质、颜色和交互表达上有明显区别，而不是仅更换主题色。
- 三套方案的信息内容和核心功能一致，能够进行公平比较。
- 用户可以明确选择一个方向，或指出希望组合的局部设计。

## 非目标

- 本轮不重构现有 React 页面。
- 不改变领域模型、本地存储、解析器和回答生成逻辑。
- 不增加登录、云同步、真实 LLM、文件上传或移动端专项设计。
- 不制作营销首页或产品功能介绍页。
